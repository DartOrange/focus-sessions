# Timer and persistence

`src/domain.ts` is a pure state machine. A session has a stable ID, mode, frozen planned duration, original start time, accumulated active milliseconds, running anchor, and running/paused state. Running elapsed is `min(planned, accumulated + max(0, now - anchor))`. Paused elapsed is accumulated only. A 250 ms refresh redraws this value; callback frequency never determines elapsed time.

Every command first reconciles a passed deadline. Completion records `anchor + planned - accumulated`, even if recovery is much later. Pause/cancel at the deadline produces completion. A terminal history row uses the original session ID. Repeated recovery cannot make another completion because the same transaction inserts the unique result and clears active state.

Within a process, time comes from a wall-clock origin plus Android `SystemClock.elapsedRealtime()` deltas, clamped nondecreasing. The small local Expo module in `modules/session-clock` exposes this clock synchronously. It includes device deep sleep and ignores wall-clock adjustments; JavaScript callbacks only refresh the display. Across restarts, persisted wall timestamps are the recovery boundary. A rollback contributes zero elapsed and writes a new anchor; a forward jump can complete the session. Finish time is clamped to original start after a rollback. Device reboot/clock changes are not authenticated. No notification, exact alarm, wakelock, or foreground service exists.

`src/controller.ts` serializes all commands and hydration on one promise queue. Each command reads the most recently acknowledged state and captures time at execution. UI state publishes after commit. A failed/ambiguous acknowledgement blocks subsequent commands until explicit reload, so queued operations cannot overwrite an unknown durable state. Repeated refreshes without a transition do not write.

`src/storage.ts` uses Expo SQLite exclusive transactions with WAL and FULL synchronization. `meta` contains schema version, preferences and the active timer. `history` has immutable terminal documents keyed by ID; `transitions` is a bounded audit of start/pause/resume/cancel/completion/reanchoring. Writes are parameterized. Terminal state, history, preferences and transition events commit together. History clearing is its own confirmed transaction and does not change an unexpired active session.

Hydration validates durations, statuses, IDs, timestamps, elapsed ranges, terminal completeness and identity consistency. Invalid active/preferences data blocks actions and offers explicit repair; raw values are quarantined on this device, no result is invented, and valid history remains. Unsupported schema versions block repair. Unreadable history rows are hidden with a count, retained through normal writes, and removed only by explicit history clearing; the 500-record retention applies to valid history. Quarantined data remains until uninstall. Whole-file SQLite corruption or unavailable storage requires restoring storage availability/reinstalling; in-app repair addresses readable databases with invalid logical records.

The UI uses three lightweight tabs with no navigation framework. Scrolling, safe-area insets, numeric keyboard inputs, platform confirmation dialogs, accessible control names and native font scaling keep core actions reachable. Fonts and geometric artwork are local. No personal history or database is packaged in the APK.
